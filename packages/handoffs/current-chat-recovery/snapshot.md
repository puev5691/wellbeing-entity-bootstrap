# Snapshot текущего рабочего чата

## Назначение

Этот файл сохраняет состояние текущего рабочего чата проекта «БЛАГОПОЛУЧИЕ» вне истории диалога, чтобы следующий экземпляр мог продолжить работу без реконструкции по памяти.

## Подтверждённое направление текущей работы

Главная работа текущего этапа: восстановление воспроизводимой роли АРХИВАРИУСА после того, как прежний длинный чат перестал нормально прогружаться, и превращение этого инцидента в общепроектную технологию сохранения состояния Сущностей.

ОПЕРАТОР сейчас работает со смартфона. Локальная рабочая область доступна только внутри `Documents` основного пользовательского хранилища. Проект предполагает смену устройств, поэтому подходящие значимые материалы решено сохранять также на GitHub.

## Что сделано

1. Изучен исторический пакет инициации `packages/core/arhivarius-v01`.
2. Подготовлен новый современный файл инициации АРХИВАРИУСА с file-first, truth-first, консультационной функцией, связью со СКРИЖАЛЯМИ, сохранением и резервированием.
3. В инициацию включён отдельный будущий программный контур АРХИВАРИУСА и ПОЧТАЛЬОНА без утверждения об их текущей работоспособности.
4. Изучен исторический handoff `packages/handoffs/0905-1204-2026-koordinator-archivist-full-context-v01`.
5. Подтверждено, что к 12 апреля 2026 года существовал реально развивавшийся MVP программного АРХИВАРИУСА. Снимок содержит исходники, README, манифест и Git-состояние.
6. Подтверждён исторический recovery-подход: рабочий контекст + снимок корня + снимок исходников + манифест + Git status/log/diff/remote.
7. ОПЕРАТОР принял решение распространить эту технологию на все Сущности проекта.
8. Создан общепроектный `entity-state-preservation-and-recovery-canon.md` и сохранён в GitHub.

## Подтверждённая историческая точка программного АРХИВАРИУСА

По handoff от 12 апреля 2026 года были реализованы и описаны: SQLite-индексация; поиск по имени и содержанию; распознавание пакетов чатов; `.wb-copy-map.tsv`; классификация и проверка покрытия; реестр Сущностей; реестр шагов; состояния `script_issued`, `script_executed`, `artifact_confirmed`; фазовый барьер; query-layer; JSON `service-query`; отдельный `service_layer.py`; path abstraction; bootstrap summary bridge.

Первый реальный прогон на живом пакете ранее зафиксировал `files_seen: 13`, `files_indexed: 13`, `files_failed: 0`, `chat_packages_found: 1`.

Это исторически подтверждённое состояние, а не утверждение о текущей работоспособности программы на нынешнем смартфоне.

## Принятый общий принцип

Каждая Сущность обязана поддерживать вне чата достаточное проверяемое состояние, позволяющее создать новый её экземпляр и продолжить работу без реконструкции по памяти.

Для этого закрепляются:

- актуальный файл инициации;
- snapshot значимого состояния;
- recovery-пакет для переноса и восстановления;
- событийное резервирование после значимых изменений;
- внешнее версионное сохранение подходящих материалов;
- фазовый барьер `выдано → выполнено → подтверждено`;
- сохранение незавершённых маршрутов;
- связь значимых результатов со СКРИЖАЛЯМИ.

АРХИВАРИУС является профильной Сущностью по технологии сохранения, но каждая Сущность отвечает за сохранение собственного состояния.

## Что намеренно не установлено

Пока не подтверждены и не должны выдумываться:

- единый домашний путь АРХИВАРИУСА внутри `Documents`;
- календарная периодичность backup;
- число поколений резервных копий;
- единый формат snapshot и манифеста;
- фактическое состояние локальной программы АРХИВАРИУСА;
- фактическое состояние ПОЧТАЛЬОНА;
- актуальность старых локальных абсолютных путей;
- полный перечень несохранённых результатов прежнего чата АРХИВАРИУСА.

## Понятийная работа, которую нельзя потерять

Параллельно ведётся развитие понятийной модели проекта. Подготовлен независимый рабочий разбор понятия «Мера». Следующий этап после получения параллельной независимой разработки: сравнить варианты на одинаковых вопросах и случаях, оформить документ расхождений, и только затем переходить к версии `Мера v0.2`.

Общий принцип работы со СКРИЖАЛЯМИ: исходный материал → кандидатное положение → проверка/сопоставление → устойчивое положение → утверждённый слой СКРИЖАЛЕЙ. АРХИВАРИУС должен сохранять происхождение, альтернативы, возражения и результаты проверок.

## Следующий безопасный шаг

Для линии восстановления АРХИВАРИУСА следующий шаг: сохранить актуальный файл его инициации во внешнем репозитории, затем при запуске нового чата дать ему этот файл и поручить read-only инвентаризацию доступной среды до любых миграций или перестроений.
